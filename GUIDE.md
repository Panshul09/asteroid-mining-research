# Click-by-click guide

This guide is for Windows and VS Code. The project is separate from the A-Level Study Planner; keep it in its own folder.

## A. Open the project in VS Code

1. Extract the project ZIP to a convenient location, such as `Documents`.
2. Open VS Code.
3. Click **File → Open Folder...**.
4. Select the `asteroid-mining-research` folder and click **Select Folder**.
5. In the left Explorer panel, expand `figures` and double-click a PNG if you simply want to view a graph. The four graphs are already included; you only need to regenerate them after changing the analysis inputs or code.

## B. Run the analysis

1. In VS Code, click **Terminal → New Terminal**.
2. Make sure the terminal path ends in `asteroid-mining-research`.
3. Run:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe src\run_all.py
```

4. When the command finishes, expand `results` in the Explorer. Open `baseline_results.txt` to read the main numbers. Open the CSV files for detailed sensitivity data.
5. Expand `figures` and double-click each PNG to view the refreshed graphs.
6. Run the checks:

```powershell
.venv\Scripts\python.exe -m pytest
```

The model inputs live in `src/model.py` (`ModelInputs`). `data/assumptions.csv` documents the values, but it is currently generated by the script; changing only the CSV will not change the model. If you deliberately test a model input, change it in `src/model.py`, save, rerun `src\run_all.py`, inspect the output files, and explain the result. Do not use arbitrary changes as evidence about real asteroid mining.

## C. Edit the manuscript and produce the final PDF

1. Open `paper_final.docx` in Microsoft Word for the web or LibreOffice Writer.
2. Rewrite/adjust the text while checking the cited sources. The graphs are embedded already.
3. The Markdown file `paper/paper.md` is a separate file. It does not update automatically when the DOCX changes. Before public release, keep the prose, figures, and results consistent in both.
4. After the GitHub repository is created, replace `[ADD GITHUB REPOSITORY URL BEFORE PUBLIC RELEASE]` in both the DOCX and `paper/paper.md` with the real repository URL.
5. In Word for the web, use **File → Export/Download as PDF**. In LibreOffice Writer, use **File → Export As → Export as PDF**.
6. Save/export the result as `paper.pdf` in this project folder, replacing the existing draft PDF.
7. Open the new `paper.pdf` and inspect every page. Check figures, captions, references, equations, page breaks, and the repository URL before uploading it publicly.

## D. Create a GitHub repository in the browser

1. Go to `https://github.com` and sign in.
2. Click the **+** icon in the upper-right corner.
3. Click **New repository**.
4. Enter `asteroid-mining-research` as the repository name.
5. Add a short description such as `Independent literature review and Python scenario analysis of asteroid-mining economics`.
6. For the first upload, choose **Private** so the manuscript placeholder is not public while you finish the repository link. You can make it public after the paper and PDF are final.
7. Leave **Add a README file**, **Add .gitignore**, and **Choose a license** unchecked. The project already contains these files.
8. Click **Create repository**.
9. Copy the repository URL shown on the next screen. It will look like `https://github.com/YOUR-USERNAME/asteroid-mining-research.git`.

## E. Upload the local folder from VS Code

The extracted ZIP contains the project files but does not contain your Git history. Use these commands from the project root.

1. Go back to VS Code and click **Terminal → New Terminal**.
2. Run:

```powershell
git init -b main
git add .
git status
git commit -m "Add reviewed asteroid mining research project"
```

3. If Git says it does not know your name/email, set them once using your own details:

```powershell
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
```

Then repeat the `git add .` and `git commit` commands.

4. Connect the local folder to GitHub. Replace the example URL below with the URL you copied:

```powershell
git remote add origin https://github.com/YOUR-USERNAME/asteroid-mining-research.git
git push -u origin main
```

5. If GitHub asks you to sign in, complete its browser/credential prompt.
6. Return to the repository page in your browser and refresh it. You should see `README.md`, `paper_final.docx`, `paper.pdf`, `paper/`, `src/`, `data/`, `results/`, `figures/`, and `tests/`.
7. Replace the placeholder `[ADD GITHUB REPOSITORY URL BEFORE PUBLIC RELEASE]` in `paper_final.docx` and `paper/paper.md` with the real repository URL. Export a fresh PDF to `paper.pdf`, inspect it, and push the changes using the commands in section F.
8. Once there are no placeholders and everything has been checked, you can make the repository public: on GitHub, open the repository → **Settings** → **General** → scroll down to **Danger Zone** → **Change repository visibility** → choose **Public** and follow the confirmation steps. Only do this if you want everyone to be able to view the paper and code.

If `git init -b main` says the branch already exists or `git remote add origin` says the remote exists, stop and check `git status` and `git remote -v` rather than repeating commands blindly.

## F. Upload later changes

When you edit the paper, replace the PDF, or rerun the model, GitHub will not automatically receive those changes. In the VS Code terminal, from this project folder, run:

```powershell
git add .
git commit -m "Update paper and scenario analysis"
git push
```

Then refresh the GitHub repository page to verify that the files changed.

## G. Archive the project with a DOI on Zenodo

Zenodo is a research-output archive, not a peer-reviewed journal. A DOI makes a record easier to cite and find; it does not mean the paper has been peer reviewed.

1. Finish the manuscript and replace the GitHub URL placeholder first.
2. Open the final `paper.pdf` and check every page. Confirm that the repo URL is correct and that there are no unfinished placeholders.
3. Go to `https://zenodo.org` and create/sign in to an account.
4. Click the **+** button in the header, then **New upload**.
5. Click **Upload files**. Select the final `paper.pdf` and, if you want to archive the code with the paper, the ZIP of the complete project. You can make a ZIP by right-clicking the project folder in File Explorer and selecting **Compress to ZIP file** (wording can differ by Windows version). Do not upload a folder containing `.venv`.
6. Fill in the title: `The Technological and Economic Constraints of Asteroid Mining`.
7. Add yourself as creator/author and write a brief description explaining that this is an independent literature review with a simplified Python scenario model.
8. Add keywords such as `asteroid mining`, `space resources`, `in-situ resource utilization`, `techno-economic analysis`, and `sensitivity analysis`.
9. Select the closest accurate resource type offered by the form. Do not label it a peer-reviewed journal article. If the record is for an unpublished manuscript, describe it as an independent research paper or preprint, as appropriate.
10. Choose a license only after reading what permissions it grants. The paper and the code can have different licensing needs.
11. Save the draft, review all metadata and files, and only then click **Publish**.
12. Copy the DOI and public Zenodo record URL. Keep them in your README or project description if appropriate.

Important: Zenodo warns that after a record is published, its files cannot simply be edited or removed from that version. Check the PDF, repository link, author name, metadata, and ZIP before clicking Publish. If you later make a substantive change, publish a new version/record according to Zenodo's versioning process.

## H. Is this a journal publication?

No. A public GitHub repository is for code and files. A Zenodo record archives the output and can assign a DOI. Neither is the same as a peer-reviewed journal publication. For a real journal submission, read that journal's author instructions, peer-review process, AI disclosure rules, and fee policy, and consider asking a knowledgeable teacher or researcher to review the study first. Do not describe the paper as peer-reviewed unless it has actually completed peer review.
